# Reading GraphAr graphs from S3

This guide configures **duckdb-graphar** with DuckDB 2.0.0 and Apache Arrow
23.0.0. It applies to DuckDB used from the CLI, Python, or Java/JDBC.

## Before you start

- Install or load a `duckdb_graphar` extension binary built for the exact
  DuckDB version and platform used by the host.
- Make the S3 bucket, GraphAr YAML files, and graph data objects accessible to
  the process. The initial `Graph.yaml` alone is not sufficient: GraphAr also
  opens vertex/edge metadata, counts, offsets, and data chunks.
- Configure **Arrow S3** to read the graph metadata. For Parquet chunks with
  the default `graphar_internal_reader_type='auto'`, configure **DuckDB
  `httpfs`** as well. These are separate S3 clients with separate settings.

A DuckDB `CREATE SECRET` **does not configure Arrow S3**. In particular, it
cannot by itself supply Arrow's credentials, custom endpoint, or region.

## 1. Supply Arrow S3 credentials and endpoint

For local testing or a service that uses explicit access keys, make these
variables visible to the **DuckDB host process before it starts**:

```sh
export AWS_ACCESS_KEY_ID='YOUR_ACCESS_KEY'
export AWS_SECRET_ACCESS_KEY='YOUR_SECRET_KEY'
export AWS_REGION='<S3_REGION>'
export AWS_ENDPOINT_URL_S3='https://s3.example.com'
```

This example targets an S3-compatible endpoint. Replace the region and URL
with the values for your service. `AWS_ENDPOINT_URL_S3` includes `https://`;
for standard AWS S3 it can be omitted. A custom endpoint is important for
S3-compatible storage because otherwise Arrow may try to discover the bucket
region using AWS endpoints. Arrow 23.0.0 prefers `AWS_ENDPOINT_URL_S3` over
`AWS_ENDPOINT_URL`; setting both is **not** necessary.

For temporary credentials, also set `AWS_SESSION_TOKEN`. Instead of explicit
keys, Arrow can use the AWS SDK C++ default credentials provider chain (for
example, an AWS profile or a supported workload identity). Set `AWS_PROFILE`
and the appropriate AWS configuration when using a profile. `AWS_REGION` is
the standard region variable for AWS SDK C++; `AWS_DEFAULT_REGION` may also
be set for tools such as boto3 that use it.

**Java/JDBC example:** if Java reads `S3_ACCESS_KEY_ID` and
`S3_SECRET_ACCESS_KEY` solely to create a DuckDB Secret, Arrow still needs
its own credentials. If these values are already in the process environment,
the process launcher can expose the same values using the AWS names, before
starting Java:

```sh
export AWS_ACCESS_KEY_ID="$S3_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="$S3_SECRET_ACCESS_KEY"
export AWS_REGION='<S3_REGION>'
export AWS_ENDPOINT_URL_S3='https://s3.example.com'
```

No modification to the Java or Python source code is required for this
environment-based configuration. `CREATE SECRET` alone is not a substitute.

## 2. Configure DuckDB `httpfs` for Parquet chunks (default mode)

The default reader setting is `graphar_internal_reader_type='auto'`:
GraphAr/Arrow reads graph metadata and DuckDB `read_parquet` reads Parquet
chunks. Load `httpfs` and create a DuckDB S3 Secret with access to the same
storage service:

```sql
LOAD httpfs;
LOAD '/path/to/duckdb_graphar.duckdb_extension';

CREATE OR REPLACE SECRET graphar_s3 (
    TYPE s3,
    PROVIDER config,
    KEY_ID getenv('AWS_ACCESS_KEY_ID'),
    SECRET getenv('AWS_SECRET_ACCESS_KEY'),
    REGION '<S3_REGION>',
    ENDPOINT 's3.example.com',
    URL_STYLE 'path',
    USE_SSL true
);
```

Here DuckDB's `ENDPOINT` is a **hostname**, without `https://`. DuckDB's
`USE_SSL true` selects HTTPS. Arrow's environment setting is instead the full
URL `https://s3.example.com`. If credentials are temporary, add
`SESSION_TOKEN getenv('AWS_SESSION_TOKEN')` to the secret.

For AWS S3, omit `ENDPOINT` and choose the appropriate region and URL style.
For an alternate S3-compatible storage service, use the endpoint, region,
URL style, and TLS settings required by that service.

The DuckDB `config` provider is supplied by `httpfs`; the separate `aws`
DuckDB extension is needed only for DuckDB's `credential_chain` provider,
not for the `config` example above.

If direct file reading through DuckDB `httpfs` already works, that verifies
only the DuckDB side. It does not verify Arrow's access to GraphAr YAML.

## 3. Attach the graph and read it twice

```sql
ATTACH 's3://rnd-grapher-graph-output/graphar/friends/lpg/23-01-01/FriendsGraph.yaml'
AS friends (TYPE duckdb_graphar);

SELECT _graphArVertexIndex FROM friends.main.person LIMIT 1;
SELECT _graphArVertexIndex FROM friends.main.person LIMIT 1;
```

Replace the graph URI, catalog name, and vertex table name for your dataset.
The correct form for the catalog alias is **`AS friends`** (not a `name`
option in the `ATTACH` parentheses).

The two queries are separate requests and must not require a second AWS SDK
initialization. They do not, by themselves, test multichunk reads or
concurrent connections.

## 4. Optional: use Arrow for ordinary vertex/edge scans

When you want to read Parquet property chunks using Arrow rather than
DuckDB, set:

```sql
SET graphar_internal_reader_type = 'arrow';
```

In this mode, the regular vertex/edge scan path uses GraphAr/Arrow for data
files as well as metadata. However, **not every GraphAr SQL function is
implemented exclusively through this reader selection**. For example,
`read_hop_filtered` uses a DuckDB-backed edge reader. Do not assume that
setting `arrow` eliminates all possible need for DuckDB `httpfs`.

To return to the default:

```sql
SET graphar_internal_reader_type = 'auto';
```

## 5. Trusted TLS certificates

For public-CA certificates, normally **no custom CA path is required**.
The native TLS backend uses its default trust store. The extension does not
disable certificate verification.

If your S3-compatible endpoint uses an internal CA, make its trusted PEM
bundle or certificate directory available to the native process before the
extension is loaded. The extension checks, in precedence order:

1. `AWS_CA_BUNDLE`
2. `SSL_CERT_FILE`
3. `CURL_CA_BUNDLE`
4. `REQUESTS_CA_BUNDLE`

The first non-empty value is used as a CA file, or as a CA directory if the
path names an existing directory. `SSL_CERT_DIR` is also considered when it
names a single existing directory; directory-list values are left to the
native TLS backend. **Only custom CA configuration is done at extension
load**; AWS SDK initialization remains lazy until the first Arrow S3 access.
An invalid explicit bundle can cause a TLS failure when connecting.

The presence of `CURL_CA_BUNDLE` or `REQUESTS_CA_BUNDLE` in a Python/Java
process can therefore influence the native GraphAr S3 connection. This is
part of the extension's current CA-precedence policy, not an AWS credentials
setting. The Java JKS/PKCS12 trust store is **not automatically imported**
into the native AWS SDK trust store. The same private CA may need separate
configuration for DuckDB `httpfs` (see DuckDB's `ca_cert_file` setting).

Arrow documents platform-specific limitations for custom CA paths on
macOS/Windows; check the TLS behavior of the selected native backend.

## 6. Important lifecycle notes

Loading `duckdb_graphar` does not itself initialize AWS S3. Arrow's `s3://`
filesystem factory invokes `EnsureS3Initialized()` on first use and handles
concurrent initialization. Repeated `ATTACH` and `SELECT` operations must not
require another `Aws::InitAPI()`.

`DETACH` disconnects a GraphAr catalog; it does not unload the extension or
shut down AWS S3. The extension does not expose
`duckdb_graphar_finalize_s3()` in the supplied replacement version. Once
Arrow `FinalizeS3()` has run, S3 cannot be initialized again in that process.
The extension does not promise an automatic host-independent shutdown hook.

## Troubleshooting

- **DuckDB `read_parquet` succeeds, GraphAr `ATTACH` fails:** check Arrow's
  credentials, `AWS_REGION`, and `AWS_ENDPOINT_URL_S3`. DuckDB Secrets do not
  configure Arrow.
- **GraphAr `ATTACH` succeeds, selecting properties fails:** check `httpfs`
  and the S3 Secret when using the default `auto` reader, and check the
  referenced GraphAr chunk objects.
- **TLS verification fails:** check the trusted CA chain for the native AWS
  SDK and, independently, for DuckDB `httpfs`; do not disable verification.
- **The Java sample has only `S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`:**
  expose those credentials under the AWS names before the JVM starts, or
  configure another supported AWS SDK credentials provider.
- **A second read fails:** capture the error; a successful first scan does not
  prove that all required property groups or chunks are reachable.
